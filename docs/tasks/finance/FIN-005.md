# FIN-005 — One-off Planned Expenses

Status: IMPLEMENTED — automated validation passed; phone acceptance pending

## Authoritative contract

This task implements the supplied FIN-005 contract: one-off future EXPENSE planning,
not automatic recurring confirmation. It supersedes older references to FIN-005 as
automatic mode in FIN-004 and ADR-009. No scheduler, income, transfer, recurrence,
notification, bank sync, FX, AI forecasting or cash-flow chart is included.

An owned PlannedExpense has Id, UserId, trimmed required Name, owned AccountId,
owned Expense CategoryId, ExpectedAmount (positive Transaction numeric(19,4)
precision/range), ScheduledDate (local DateOnly), optional normalized Note and UTC
CreatedAtUtc/UpdatedAtUtc. Account currency is authoritative. Only unprocessed
items can edit these fields; Cancelled requires explicit Restore first. Confirmed
metadata cannot rewrite actual history.

Reject DateOnly.MinValue/MaxValue because the PostgreSQL provider maps those
sentinels to infinities; supported scheduled dates are finite calendar dates
0001-01-02 through 9999-12-30. App query dates use invariant Gregorian formatting.

Projected means scheduled after local Today; Due means on/before Today and
unprocessed. Today uses TimeProvider and the validated FIN-004 UTC offset.
Confirmed links a real Transaction; Cancelled records an explicit cancellation.
There is only one logical occurrence per expense. Projected, Due and Cancelled
have no accounting effect. Analytics, balances and history remain actual-only.

Only Due may be manually confirmed after compact review of name, account,
category, expected amount/date, editable actual amount/local date-time/note.
Confirmation validates ownership and references and creates a normal Expense
Transaction plus confirmation linkage atomically. Retries reveal the existing
Transaction. Serializable row locking, bounded retries and database uniqueness
prevent concurrent duplicate confirmations.

Projected/Due may Cancel. Cancelled may Restore to its derived state; Confirmed
cannot Restore. All planning metadata may be deleted after explicit UI confirmation,
including Confirmed; actual Transactions always survive. Ordinary Transaction
deletion atomically removes confirmation linkage and reopens a surviving plan.
Account/category deletion is restricted by any surviving plan, with meaningful
conflict responses and ownership-safe PostgreSQL FKs.

## Persistence decision

Use planned_expenses plus planned_expense_states (Confirmed/Cancelled only).
The small state table mirrors FIN-004: deleting an actual Transaction cascades
only its state, without custom triggers or a nullable composite SET NULL that
would clear the required owner. Unique expense linkage and unique Transaction
linkage, status shape checks, positive amounts, and composite ownership FKs are
database backstops. Add a migration; never modify historical migrations.

## Budget and UX

ExpectedRecurringExpenses retains its meaning. ExpectedPlannedExpenses includes
only Projected/Due items scheduled in the selected calendar month for owner and
currency. ExpectedExpensesTotal is their sum. Spent is actual Expense Transactions;
Remaining = Budget - Spent; FreeToSpend = Remaining - ExpectedExpensesTotal;
SafeDailySpend uses FreeToSpend. Read actual and both planning types coherently.
Same-month equal confirmation preserves FreeToSpend; amount overrides change it
by the delta. Cross-month confirmation removes the scheduled expectation while
spending belongs exclusively to the actual Transaction's month.

Finance → Planned expenses provides bounded range management, create/edit,
cancel/restore/delete and actual links. No bottom navigation addition. Transactions
combines distinct Recurring and One-off groups within Planned for the selected
month. Due one-off offers inline Review & Confirm/Cancel; Projected offers Cancel
only. Confirmed/Cancelled leave unresolved planning. Action completion and month
navigation refresh planning and actual history. Reuse existing FIN-004 review
patterns and decimal/local-time helpers. Home shows aggregate budget values only.

- Application CRUD, bounded date queries/get, owned references, cancel/restore,
