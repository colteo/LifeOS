# FIN-002 — Portfolio amount privacy

Status: READY

## Goal

Allow the user to temporarily hide monetary amounts related to their portfolio
when using LifeOS around other people.

This is a presentation/privacy preference.

It is not Finance business data.

## Product behavior

Add a visible show/hide control associated with Portfolio.

When portfolio amounts are visible:

show current behavior.

When hidden:

replace portfolio monetary values with a neutral obscured representation such
as:

••••••

Do not replace values with zero.

Currency labels, account names and structural information may remain visible.

## Scope

The privacy state must apply to:

- Home Portfolio card;
- Portfolio page total amounts;
- Portfolio page per-account monetary amounts.

## Explicit exclusions

FIN-002 must NOT hide:

- transaction amounts;
- Analytics values;
- budget values;
- SafeDailySpend;
- account names;
- currency codes;
- transaction history.

This can be reconsidered later if a broader "privacy mode" is desired.

## Persistence

The preference is DEVICE-LOCAL.

It must persist across app restarts on the same device.

No API.

No database column.

No migration.

No server synchronization.

Use an existing LifeOS preference/settings abstraction if one exists.

Otherwise use the simplest appropriate MAUI local-preference mechanism without
introducing a new dependency.

## UX

Use the existing LifeOS icon system.

Do not use emoji.

The control should communicate:

- Show portfolio amounts
- Hide portfolio amounts

with appropriate accessibility labels.

The same preference state must be reflected consistently on Home and Portfolio.

Do not redesign the Portfolio page.

Do not redesign the global shell.

## Security clarification

This is visual privacy only.

It is NOT intended as encryption, authentication or protection against a user
with access to the device.

Document this only if necessary; do not add alarming UI copy.

## Tests

Cover where practical:

- default visible state;
- toggle to hidden;
- toggle back to visible;
- persistence across preference reload;
- Home and Portfolio use the same preference;
- transaction/budget/analytics formatting remains unaffected.

## Non-goals

Do NOT implement:

- PIN protection;
- biometric lock;
- screenshot prevention;
- global application privacy mode;
- server-side storage;
- per-currency privacy settings.

## Stop conditions

STOP if implementation requires:

- API changes;
- database changes;
- Authentication changes;
- a new external dependency;
- modification of Finance business logic.

## Validation

Run the same standard checks required by the Finance branch:

- UnitTests;
- IntegrationTests;
- ArchitectureTests;
- Android Debug build;
- migration/model consistency checks.

No migration is expected from FIN-002.

## Definition of done

FIN-002 is done when:

- the user can hide/show portfolio values;
- state persists locally;
- Home and Portfolio stay consistent;
- no unrelated monetary values are hidden;
- automated checks pass;
- phone acceptance steps are documented.

## Final report

Include FIN-002 in the Finance branch final report together with FIN-001.
