# NAV-001 — Bottom navigation refresh and Home Finance card

Status: IMPLEMENTED — automated validation passed; phone acceptance pending

Branch: `improve/navigation-finance-home`. Baseline: `main` @ `a024c23`
(after NUT-003 target plans).

## Scope

App presentation and navigation only. No Domain, Application, Infrastructure,
API, contract, EF model, migration, Python or deployment change. No new package,
icon library or modal/sheet package.

## Rationale

- **The dock is high-frequency shortcuts, not the sitemap.** It holds the places
  used several times a day: Home, the transaction history, the Food diary, and a
  global quick add.
- **More is the sitemap.** It stays the module directory (Finance, Gym,
  Nutrition) and every module keeps its hub there. A dock shortcut never removes
  module-level navigation.

## Final dock

```text
Home | Transactions | + | Nutrition | More
```

| Item         | Destination              | Icon           |
|--------------|--------------------------|----------------|
| Home         | `/`                      | `home`         |
| Transactions | `/finance/transactions`  | `transactions` |
| +            | quick-add panel (action) | `plus`         |
| Nutrition    | `/nutrition` (Food diary)| `nutrition`    |
| More         | `/more`                  | `grid`         |

The dock keeps its identity: rounded floating white bar, dark raised central
"+", the AppIcon line icons, safe-area padding, the same height
(`--lo-dock-height`), and it still hides while a text field has focus. The bar
uses five columns (`1fr 1fr 3.75rem 1fr 1fr`): at ~360dp each destination gets
about 69px, enough for "Transactions" at the dock label size; labels ellipsize
instead of overlapping if a device font is unusually wide.

## Active-state rules

Implemented centrally in `Services/Navigation/DockNavigation.cs` on the
normalized path (query, fragment, leading/trailing slashes and case removed).
At most one item is active; sections match whole path segments only.

| Path                                                      | Active       |
|-----------------------------------------------------------|--------------|
| `/`                                                       | Home         |
| `/finance/transactions`, `/{id}`, `/{id}/edit`            | Transactions |
| `/finance/transactions/new`                               | none         |
| `/nutrition` (and any nested diary route)                 | Nutrition    |
| `/nutrition/hub`, `/nutrition/targets/…`                  | More         |
| `/more`                                                   | More         |
| `/finance` and its management screens (accounts, categories, analytics, planned expenses, recurring) | More |
| `/gym/…`                                                  | More         |
| `/settings`, `/portfolio`                                 | none         |

"+" is never active. It is a `<button>` with `aria-expanded`/`aria-controls`,
not a link.

## Global quick add

"+" opens a compact panel above the bar, in the LifeOS card style, titled
**Add**:

- **Transaction** → `/finance/transactions/new` (the existing quick-entry flow).
- **Meal** → `/nutrition?add=meal`.

The choices are links with accessible names "Add transaction" / "Add meal".
The panel closes on a choice, on a tap of the dimmed backdrop, on Escape, on a
second tap of "+" (which shows a close icon while open) and on any navigation.
Workout start is deliberately not offered: it is not a generic quick-create.

**Meal flow.** Quick-add Meal **always adds a meal for today**. The Food diary
reads `?add=meal` (`[SupplyParameterFromQuery]`) as that intent and:

1. replaces the URL with `/nutrition` first, so Back, a reload or a later visit
   never reopens the form;
2. switches the diary to local today if it showed another day (the same day
   change the ‹ › arrows use: list, totals and target reload for today);
3. opens its own add form — the same form as "+ Add meal".

It does not depend on the day the diary last showed. The page's own
"+ Add meal" is unchanged: it adds to the day on screen (e.g. yesterday after
‹). There is no second meal form and the dock contains no Nutrition logic; the
query name and value are constants in `DockNavigation`.

## Home Finance card

Home stays: greeting, **Finance**, **Training**, **Nutrition**. Training and
Nutrition are unchanged; each card still loads and fails on its own.

```text
Finance                                      Open      → /finance

┌──────────────────────────────────────────────────┐
│ Monthly budget                              Edit │
│ October 2026 · EUR                               │
│ 998,00 EUR                                       │
│ free to spend                                    │
│ ▬▬▬▬▬▬▬▬▬▬▬▬ (spent progress)                     │
│ 2,00 EUR spent of 1.000,00 EUR                   │
│ 0,00 EUR expected                                │
│ 36,96 EUR/day safe to spend                      │
│ ──────────────────────────────────────────────── │
│ [ Portfolio ]                 [ Analytics ]      │
└──────────────────────────────────────────────────┘
```

- **Finance** is the module heading; **Open** goes to the Finance hub.
- **Monthly budget** is a subheading inside the card, with **Edit** when a
  budget exists.
- **Free to spend** is the leading figure (red if negative). Spent of budget,
  expected and safe/day follow; month and currency are secondary.
- "remaining" is shown only when the budget is exceeded
  ("… remaining · Budget exceeded"), so it does not compete with free to spend.
- All values come from the budget API unchanged; no calculation was added.
- No budget: "No October 2026 budget." with **Set budget**; the card remains.
- Loading, API error (Retry), editing and removal confirmation are unchanged.
  Set / Edit / Remove and their validation behave as before.
- **Portfolio** (`/portfolio`) and **Analytics** (`/finance/analytics`) stay at
  the bottom of the card in every state.
