# APP-001 — Cross-module Home and Navigation

Status: READY

## Goal

Make LifeOS feel like a multi-domain personal operating system rather than a
Finance app with other modules hidden inside it.

1. Replace the Finance-centric global navigation with a cross-module shell.
2. Make Home visibly represent more than Finance.

APP-001 changes the information architecture of the application shell. It is
not a general visual redesign, and it does not redesign module screens.

## No schema change expected

APP-001 is client-only. No backend endpoint, no migration. If a migration
appears necessary: stop and explain why.

## Global navigation

Before:

```text
Home | Portfolio | + | Transactions | More
```

After:

```text
Home | Finance | + | Gym | More
```

| Item    | Target                                          |
|---------|-------------------------------------------------|
| Home    | `/`                                             |
| Finance | `/finance`                                      |
| +       | `/finance/transactions/new` (New Transaction)   |
| Gym     | `/gym`                                          |
| More    | `/more`                                         |

The central + remains New Transaction. No global multi-action quick-add menu
yet; the dock must not prevent replacing + with a multi-module action sheet
later.

Labels: Home, Finance, Gym, More. The center + has an accessible label
("New transaction") and no visible text label. Existing icons are reused.

## Active navigation

Active state reflects modules, not individual Finance screens.

| Section | Active on                                               |
|---------|---------------------------------------------------------|
| Home    | `/` only                                                |
| Finance | `/finance`, `/finance/*`, `/portfolio`                  |
| Gym     | `/gym`, `/gym/*`                                        |
| More    | `/more` (and future modules without their own dock item)|

- The New Transaction action (`/finance/transactions/new`) selects nothing.
- `+` is an action, never an active section.
- Settings selects no dock item.

## Top-level module hubs

Finance and Gym are first-class dock destinations, therefore:

- FinanceHub shows no "Back → More".
- GymHub shows no "Back → More".

Child pages keep linking back to their module (Accounts, Categories, Planned
expenses, Recurring, Analytics, Transactions, Portfolio → Finance; Train,
History, Programs → Gym). Normal browser/device back behavior is preserved; no
artificial navigation stacks.

Portfolio, no longer a dock item, is reachable from the Finance hub and from
Home.

## More

More remains the module directory / overflow area. Settings is not moved into
More; it stays reachable from the header.

Chosen behavior: More keeps listing every shipped module (Finance and Gym) for
discoverability. A future module without its own dock entry is added to More
and More is the selected dock item on that module's routes.

## Home — product role

Home is a cross-module summary answering "What matters now in LifeOS?". It must
no longer communicate that Finance is the whole product. Each module
contributes one self-contained summary component; a future module (e.g.
Nutrition) adds its own summary without changing the shell. No plugin framework.

Conceptual structure (guidance, not a mandatory literal layout):

```text
Home
├── Today
│   └── Workout in progress / Resume  OR  compact Gym / Train entry
├── Finance
│   ├── Portfolio summary
│   └── Monthly budget (includes the safe daily-spend signal)
└── Recent activity
    └── Recent transactions
```

Must remain useful at ~360dp Android width.

### Gym on Home

Existing APIs/read models only.

- Workout InProgress → show the existing workout-in-progress information
  prominently and expose Resume.
- No workout in progress → compact Gym entry/state exposing Train.
- Optional: most recent completed workout, only if cleanly available through
  the GYM-003 history read model.

Not invented here (GYM-004): today's scheduled workout, next workout, weekly
adherence, streaks, training schedules.

### Finance on Home

Preserve monthly budget, portfolio summary and recent transactions, presented
as one domain on Home rather than the definition of Home. Finance business
calculations are unchanged.

## Failure isolation

Home sections load and fail independently. Gym current-session failure does
not block Finance content; Finance failures do not suppress Gym content. Home is
never one all-or-nothing request state.

## Performance

No N+1 calls. Minimum existing API calls; compose existing module clients. No
backend Home aggregation endpoint.

## Accessibility

Preserve/improve aria-labels, `aria-current`, meaningful link text,
focus-visible states and comfortable tap targets. Navigation state is not
communicated only by icon/color.

## Visual scope

Preserve typography, colors, dark primary, cards, dock shape, spacing tokens and
header. Layout/spacing adjustments only where the new information architecture
needs them. No new design system (UI-001 handles visual consolidation).

## Phone acceptance (~360dp)

1. Launch → Home visibly contains both Finance and Gym context.
2. Dock shows Home / Finance / + / Gym / More.
3. Tap Finance → Finance module opens directly.
4. Portfolio, Transactions, Accounts, Analytics → Finance stays selected.
5. Tap Gym → Gym hub opens directly.
6. Train, History, Programs → Gym stays selected.
7. Start a workout → Home shows Resume prominently.
8. Finish/discard → Home returns to the non-active Gym state with Train.
9. + still opens New Transaction and the transaction flow works.
10. More remains usable as the module/overflow directory.
11. No top-level Finance/Gym page shows a misleading "Back to More".
12. Long labels, 360dp width and the Android navigation bar do not overlap the
    dock.

## Implementation notes

- Dock active rules live in `Services/Navigation/DockNavigation.cs` (plain .NET,
  unit-tested). Dock items carry a `DockSection`; the central + carries
  `DockSection.None`, so it can later become an action sheet without touching
  the active rules. The selected item is marked by `aria-current="page"`, color
  and an underline on its label.
- Home is composed of `HomeSection`s (`Components/Home/`), each wrapping one
  self-contained summary that loads and fails on its own:
  - Today → `GymHomeSummary`: one `GET current session`; only when nothing is in
    progress, one read of the first history page for the last completed workout
    (omitted silently if that read fails).
  - Finance → `FinanceHomeSummary`: portfolio (balances) and `MonthlyBudgetCard`.
  - Recent activity → `RecentTransactionsSummary`.
  A future module adds one summary component and one `HomeSection` on Home.
- The daily-budget signal stays inside the monthly budget card (safe daily
  spend) rather than being duplicated into Today, to avoid a second budget read.
- Portfolio is listed first on the Finance hub and links back to Finance.
- Same API calls as before APP-001 for Finance (balances, accounts, categories,
  recent), plus Gym current session and at most one history page.
