## UX states

### Timeline (`/journal`)

- **New entry** button at the top.
- **Loading:** "Loading journal..." while the first page loads.
- **Error (first page):** the API message with **Retry**.
- **Empty:** "No journal entries yet." with a hint to use New entry.
- **Rows:** occurred date/time (device local, see below), the title when
  present, and a two-line content preview (whitespace and line breaks collapsed,
  cut at ~140 characters on a word boundary with "…"). A row opens the entry.
- Order is **exactly the API order** (newest first: occurred at, then created
  at, then id). The App never re-sorts.

### New entry (`/journal/new`)

- **Occurred at** (`datetime-local`, minute precision) defaults to *now* in the
  device's local time.
- **Title (optional)** and **Content**, each with a live `length / max` counter
  (red when over).
- Save → the new entry's detail page replaces the form in history. Cancel →
  timeline.

### Entry detail (`/journal/{id}`)

- Title (if present), long local date/time, full content with its line breaks
  (`white-space: pre-wrap`).
- **Edit entry** and, set apart, **Delete entry**.
- **404** (missing, already deleted, or another user's — identical in the API):
  "This journal entry no longer exists." with **Back to journal**, no Retry.
- **Other errors** (network, timeout, 5xx): the message with **Retry**.

### Edit entry (`/journal/{id}/edit`)

- Loads the entry from the server (works after a reload); same loading / 404 /
  error states as detail.
- All three fields editable. Save replaces occurred at, title and content
  (JRN-001 full-replacement PUT). **Leaving the title blank sends `null`, which
  removes it.**
- While the date/time text is unchanged, the stored instant is sent back
  exactly (seconds and microseconds kept), as the transaction editor does.
- Save → detail page (history replaced). Cancel → detail.

### Validation (client-side, mirrors JRN-001; the API stays authoritative)

| Rule | Message |
| --- | --- |
| Content required (blank/whitespace) | "Write something in the entry." |
| Title ≤ 200 after trimming | "Title must be at most 200 characters (N now)." |
| Content ≤ 20,000 after trimming | "Content must be at most 20,000 characters (N now)." |
| Unparsable date/time | "Choose a valid date and time." |
| Local time skipped/repeated by DST | the existing `LocalDateTimeConverter` message |

**No silent truncation:** the inputs have no `maxlength` (which would cut a
paste); too-long text is an error and the entered text is kept as typed. API
400 messages (e.g. occurred-at range) are shown in the same error list. Form
values are kept on any failure; nothing is retried automatically.

## Delete confirmation

1. **Delete entry** only opens an inline confirmation panel (the existing
   transaction-detail pattern): "Delete this journal entry? This can't be undone."
2. **Delete** calls `DELETE /api/journal/{id}`; **Cancel** closes the panel.
3. On success the timeline replaces the detail page in history and reloads from
   the API, so the deleted entry is gone. A 404 on delete (already gone) counts
   as success. Other failures show the message inside the panel.

Hard delete: no undo, no soft delete.

## API usage

`Services/Journal/JournalApiClient.cs`, registered in `MauiProgram` on the
existing authorized `HttpClient` pipeline (`AuthorizationMessageHandler`: bearer
token, single-flight refresh on 401, session end), `ApiTimeouts.Default`. No
authentication logic is duplicated.

| Method | Call |
| --- | --- |
| `GetPageAsync(cursor, limit = 20)` | `GET api/journal?limit=20[&cursor=<escaped>]` |
| `GetAsync(id)` | `GET api/journal/{id}` |
| `CreateAsync(request)` | `POST api/journal` (`CreateJournalEntryRequest`) |
| `UpdateAsync(id, request)` | `PUT api/journal/{id}` (`UpdateJournalEntryRequest`) |
| `DeleteAsync(id)` | `DELETE api/journal/{id}` |

Failures become `ApiResult` errors, never exceptions:

- **400** → the per-field validation messages (`ApiErrors`).
- **401** → handled by the authorized pipeline; if the session cannot be
  refreshed the existing sign-out flow applies.
- **404** → `JournalApiClient.NotFoundMessage` (`IsNotFound(result)` lets the
  pages show the not-found state); `DeleteAsync` treats it as deleted.
- **Network errors / timeouts** → the shared "Could not reach the LifeOS API…"
  message; other statuses → the ProblemDetails message or a generic one.

Requests carry no user id; the owner is always the authenticated user.

## Pagination UX

- Page size 20 (`JournalApiClient.PageSize`, the API default).
- The first page loads on open; **Load more** appears only while the API
  returns a `NextCursor`, and appends the next page in API order.
- The cursor is opaque: passed back exactly (URL-escaped), never parsed.
- A failed Load more keeps the loaded entries and the cursor and shows the error
  under the list; Load more asks for the same page again.

## Date/time behavior

- **Display:** `OccurredAtUtc` converted to `TimeZoneInfo.Local` with the
  existing LifeOS wording (`TransactionDisplay`): list "Today 18:05",
  "Yesterday 09:30", "27 September · 14:10", "27 September 2025 · 14:10";
  detail "30 September 2026 · 13:10" (English dates, device-culture time).
- **Input:** `datetime-local` wall-clock text interpreted in the device time
  zone and converted to UTC with the existing `LocalDateTimeConverter`; the
  request's `OccurredAtUtc` has offset `+00:00`.

## Phone acceptance checklist

1. More lists Journal; it opens the timeline; More is active in the dock.
2. Empty journal shows the empty state.
3. New entry: occurred at shows the current local time; save with content only.
4. The entry appears in the timeline with local date/time and preview.
5. Add a titled entry and a back-dated entry; order is newest occurred first.
6. With more than 20 entries, Load more appends older entries, then disappears.
7. Detail shows title, local date/time and full content with line breaks.
8. Edit: change time, title and content; clear the title → it is removed.
9. Validation: empty content, 201-character title, pasted 20 001-character
   content are rejected; nothing is cut.
10. Delete: Cancel keeps the entry; Delete returns to the timeline without it.
11. Airplane mode: list/detail show an error with Retry.
12. Restart the app; the journal reloads from the API.
